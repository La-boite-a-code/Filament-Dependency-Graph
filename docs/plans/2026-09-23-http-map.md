# HTTP Map Implementation Plan

**Goal:** Ship the `http` scope (routes, controllers, form requests, route-bound models, policies, events, listeners, jobs, mailables, notifications) as release 1.2.0.

**Architecture:** New discoverers produce an `HttpMapData` section on `ApplicationSnapshot`. The graph builder turns it into new node and edge types, `BuildDependencyGraph` restricts them to the new `GraphScope::Http`, and the page, inspectors, exports and renderer learn the new types. Static source analysis is shared with the Livewire discoverer through an extracted `SourceScanner`.

**Tech stack:** PHP 8.3+, Laravel 12/13, Filament 4/5, Livewire 3, Pest, PHPStan, Pint, Cytoscape (esbuild).

**Spec:** `docs/specs/2026-09-23-http-map-design.md`

## Global constraints

- Never execute a controller action, never resolve a form request from the container, never instantiate a policy.
- Every discovery failure degrades to a warning and a `Partial` status; discovery never throws.
- DTOs are `final readonly` with `fromArray()` / `toArray()` round trips.
- Filament and Laravel scopes keep their current output.
- Pint, PHPStan and the full Pest suite pass before every commit.
- Commits are authored by Alexandre Ribes, imperative English subject, no tool attribution.
- `dist/` is rebuilt with `npm run build` whenever `resources/js` or `resources/css` change.

## Plan-time refinements of the spec

These were settled while reading the code and are reflected in the spec before release:

1. **Route identifiers** use methods (without `HEAD`), domain and URI, never the name: names can repeat, the method/domain/URI triple cannot.
2. **Dispatch detection** is class-driven: `X::dispatch*()` / `X::broadcast()` static calls and `new X` expressions are collected, and only classes that resolve to a job, mailable, notification or event are kept. This covers every pattern of the spec table (`Mail::to()->send(new X)`, `->notify(new X)`, `event(new X)`, `Bus::chain([new X])`...) without matching each call shape.
3. **Policy resolution** mirrors `Gate::getPolicyFor()` without instantiating: registered map, `#[UsePolicy]` attribute when available, then `Gate::guessPolicyName()` read through reflection, which also honours a custom `guessPolicyNamesUsing()` callback. The documented limitation disappears.
4. **Contracts**: `HttpMapDiscoverer` and `PolicyDiscoverer` are the two replaceable entry points; route, controller, form request and event discovery are internal collaborators.
5. **Events without dispatcher** get a `Not dispatched` badge; `OrphanDetector` keeps its model-only meaning and additionally treats `controller_uses_model` as a connection.
6. **Middleware filter** is a `GraphQuery::$middleware` value (`auth` keeps routes with it, `!auth` keeps routes without it), applied inside the HTTP scope traversal so export and API get it too.

## Tasks

Each task: failing tests first, implementation, `vendor/bin/pest`, `vendor/bin/phpstan analyse`, `vendor/bin/pint --test`, commit.

### Task 1: Extract `SourceScanner`

- Create `src/Discovery/Support/SourceScanner.php`: `imports(string $source, int $classStartLine): array<string,string>`, `resolveClass(string $reference, string $namespace, array $imports): ?string`, `staticClassReferences(string $source): list<string>`, `renderedView(string $source): ?string`, token helpers.
- Refactor `LivewireComponentDiscoverer` to use it. Existing Livewire tests must pass untouched.
- Test: `tests/Unit/Discovery/SourceScannerTest.php` (grouped imports, aliases, `namespace\` relative names, comments and strings ignored).

### Task 2: Method-level scanning

- `SourceScanner::forMethod(ReflectionMethod $method): ?MethodSource` returning the token slice of the method body plus the file imports and namespace.
- `MethodSource` exposes `staticCalls(): list<array{class: string, method: string, line: int}>`, `instantiations(): list<array{class: string, line: int}>`, `collaboratorCalls(): list<array{variable: string|null, property: string|null, method: string, line: int}>` (`$var->m(`, `$this->prop->m(`, `$var(` mapped to `__invoke`).
- Test fixtures: `tests/Fixtures/Http/Scanning/*.php`.

### Task 3: Domain

- `NodeType`: `Route`, `Controller`, `FormRequest`, `Policy`, `Event`, `Listener`, `Job`, `Mailable`, `Notification`, sort priorities 5..13, plus `isHttp(): bool` and `static httpTypes(): list<self>`.
- `EdgeType`: `RouteHandledByController`, `RouteRendersLivewire`, `ControllerValidatesWith`, `ControllerUsesModel`, `ModelGuardedByPolicy`, `EventHandledByListener`, `Dispatches`.
- `GraphScope::Http`.
- `DispatchKind` enum: `job`, `mailable`, `notification`, `event`.
- DTOs in `src/Domain/DTO/Http/`: `HttpMapData`, `RouteData`, `ControllerData`, `ControllerActionData`, `DispatchReference`, `FormRequestData`, `PolicyData`, `EventData`, `ListenerData`, `DispatchableData`.
- `ApplicationSnapshot::$http` (default empty), `fromArray()` tolerant of a missing key, `toArray()` emits `http`.
- `StableIdentifier`: `route()`, `controller()`, `formRequest()`, `policy()`, `event()`, `listener()`, `dispatchable(DispatchKind, string)`.
- `SchemaVersion::CURRENT = '1.3'`.
- Tests: DTO round trips, identifiers, snapshot without `http` key.

### Task 4: Configuration and context

- `config/filament-dependency-graph.php`: `http` block (spec §2) and `http_scope_enabled`.
- `DiscoveryContext`: `discoverHttp`, `httpControllerNamespaces`, `httpApplicationNamespaces`, `includeVendorRoutes`, `excludedRouteNames`, `excludedRouteUris`, `followInjectedClasses`, `invokeFormRequestRules`; all in `toArray()` and `clone()`.
- `DiscoverApplication::defaultContext()` reads them.
- `DependencyGraphPlugin::allowHttpScope()`, `scanHttp()`.
- `TestCase`: fixture namespaces for `http.*`, `fixtureContext()` defaults.

### Task 5: HTTP source inspection

- `src/Discovery/Http/DispatchClassifier.php`: class → `?DispatchKind` (Mailable, Notification, event when events `Dispatchable` trait or listener-map key or `ShouldDispatchAfterCommit`/`ShouldBroadcast`, job when bus `Dispatchable`, `Queueable` or `ShouldQueue`).
- `src/Discovery/Http/MethodInspector.php`: `inspect(ReflectionMethod, DiscoveryContext, eventClasses): MethodFindings` with `models` (class → sources), `dispatches` (list of `DispatchReference`), following collaborators one level when enabled.
- Fixtures: `tests/Fixtures/Http/Actions/CreateOrder.php`, jobs, mail, notification, events, listeners.

### Task 6: Routes

- `src/Discovery/Http/RouteDiscoverer.php` with namespace/vendor/exclusion filtering, middleware expansion, bound parameters, action type.
- `TestCase::defineRoutes()` registers controller, invokable, closure, view, redirect, Livewire and an excluded route.

### Task 7: Controllers and form requests
